# Energy-based concept acquisition through pairwise relational reasoning

## Unified Formulation

A concept can be identified or generated by making a structured candidate compatible with both a latent concept representation and the relations among its entities. In [[Concept Learning with Energy-Based Models]], this compatibility is expressed by a non-negative energy E_θ(x, a, w), where x denotes entity state trajectories, a is an attention mask, and w = [w_x, w_a] is the concept code. Low energy represents a candidate that fits the learned concept; the corresponding Boltzmann distribution is proportional to exp(-E_θ)/Z.

The energy is relational rather than merely a sum of independent judgments about isolated entities. [[A Simple Neural Network Module for Relational Reasoning]] describes pairwise computations g_θ(x_i, x_j, w), gated by attention masks and aggregated by f_φ. This provides a mechanism for representing interactions such as spatial arrangements, graph topology, and multi-entity composition—structure that unary entity encoders can miss. In the energy-based model, such relational evidence informs the joint compatibility score. The available descriptions do not specify an exact algebraic identity between f_φ and E_θ, so the safe synthesis is that pairwise aggregation supplies relational structure to the energy, not that the two named functions are necessarily identical.

There are two complementary inference targets. For concept generation, the energy-based model optimizes a candidate trajectory x^1 at execution time, with a and w providing context. For entity identification, it instead searches over attention a. The described model performs these execution-time searches using K=10 steps of Stochastic Gradient Langevin Dynamics (SGLD) over the Boltzmann distribution. The gradient directives below concern the generation target x^1; they do not substitute an attention update or assert that each noisy SGLD step strictly decreases energy.

A second route identifies what the concept code should be from examples. [[Concept Acquisition via Meta-Learning from Positive Examples]] infers a latent code w* from positive demonstrations X^demo by minimizing energy over those demonstrations. Its meta-learned prior structure helps prevent the inferred code from collapsing. This makes the code a compact, example-conditioned representation of the concept, while relational energy evaluates whether candidate entities and their configuration fit that representation.

Together, these mechanisms answer different but connected questions: pairwise relational structure says what configuration of entities is compatible with a concept; concept-code inference says which concept representation best explains the positive demonstrations. Relational structure makes compatibility sensitive to interactions, while code optimization makes the target representation adaptable from few examples.

This is a specific application, not a claim that MAML in general defines a relational energy.
- [[A Simple Neural Network Module for Relational Reasoning]] ↔ [[Concept Acquisition via Meta-Learning from Positive Examples]]: a latent code inferred from positive examples can condition relational computations, so demonstrations determine what relation pattern is relevant while pairwise interactions test how entities realize it. This is a conceptual interface; the notes do not specify that the positive-example method uses this particular module.
- [[Model-Agnostic Meta-Learning for Fast Adaptation (MAML)]] ↔ [[Concept Learning with Energy-Based Models]]: both describe execution-time inference coupled to learned parameters, but their inference procedures must remain distinct. MAML differentiates an outer objective through inner-loop gradient adaptation; the energy-based model samples or searches under a learned energy with SGLD. Shared use of gradients does not make these the same mechanism.

## Contradictions & Entangled Notes Reconciled

The documents use related words for different roles. In the energy-based account, energy is a learned compatibility function over entity trajectories, attention, and a concept code. In the relational module, relation refers to learned pairwise entity interactions. In MAML, gradient descent is an adaptation procedure inside a meta-learning objective. These ideas can be connected, but none should be substituted for another merely because all involve learned parameters and gradients.

In particular, the SGLD inference in [[Concept Learning with Energy-Based Models]] and the inner-loop adaptation in [[Model-Agnostic Meta-Learning for Fast Adaptation (MAML)]] are not contradictory accounts of one algorithm. They optimize or sample over different objects under different procedures: SGLD is specified for execution-time entity or attention inference under an energy-based Boltzmann distribution; MAML specifies how meta-parameters are trained through task-specific gradient adaptation. The positive-example concept method joins the latter framing to inference of a latent code by minimizing energy over demonstrations, but that application does not imply that general MAML defines pairwise relational energy.

There is also an apparent labeling conflict: MAML appears among the attended documents and is repeated in the rejected surface-word distractor list. The content resolves this if rejection is interpreted narrowly. MAML is relevant as a methodological bridge to [[Concept Acquisition via Meta-Learning from Positive Examples]], but it is not itself evidence for the specific pairwise-energy mechanism. It should therefore remain attended for the synthesis while being rejected as a stand-alone match if the selection criterion is specifically relational energy over entities or demonstrations.

Finally, the two kinds of energy inference should not be collapsed. Searching for x^1 asks which entity trajectory is compatible with a given concept context; inferring w* from X^demo asks which concept code explains the demonstrations. Their objectives are complementary, not interchangeable. Attention a further mediates which entities contribute to relational evidence, whereas the latent code w represents concept-specific information.
